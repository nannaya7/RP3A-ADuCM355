# NT-proBNP 모델 연동을 위한 요청 사항

> **수신 대상**: NT-proBNP V18 모델을 개발한 담당자
> **목적**: V18 추론 패키지(`NT-PROBNP_POCT_V18_Inference_Package`)를 Raspberry Pi 진단 장비(GUI)에 연동하기 위해 필요한 자료를 요청한다.
> **작성 근거**: 전달받은 패키지 분석 결과 ([model_nt_probnp_v18.md](model_nt_probnp_v18.md))

## 1. 배경 (한 문단)

장비는 ADuCM355 임피던스 측정 모듈이 키트를 측정하고, Raspberry Pi 3A+ (RAM 512MB, Python 3.13)의 GUI가 결과를 받아 농도를 계산해 표시한다. 전달받은 V18 패키지는 **6개의 이미 추출된 특징량**을 입력으로 받는다. 그런데 **원시 임피던스 스펙트럼에서 그 6개를 만드는 방법이 패키지에 없어**, 장비에서 특징량을 만들 수 없다. 아래 항목이 확정되어야 연동할 수 있다.

## 2. 현재 상태 요약

| 항목 | 상태 |
|---|---|
| 모델 추론 로직 (`poct_v18.py`) | ✅ 확인 완료 |
| 모델 구조 (GBR + 로지스틱 + 릿지 + NN 게이트 5개) | ✅ 확인 완료 |
| **원시 EIS → 6개 특징 변환** | ❌ **없음 (연동 불가의 직접 원인)** |
| 측정 프로토콜 (단계·시간·반복) | ❌ 모름 |
| 모델 파라미터 일부 수치 | ❌ 읽지 못함 (§R6) |
| 검증 데이터 (실측 + 정답) | ❌ 없음 |
| 임상 해석 / 표시 기준 | ❌ 모름 |

연동 방식은 **PC에서 모델 가중치를 한 번 추출하고, Pi에서는 numpy만으로 추론**하는 것으로 정했다 (torch/scikit-learn을 Pi에 설치하지 않음). 이 방식에서도 아래 요청 항목은 그대로 필요하다.

## 3. 요청 항목

우선순위: **필수**(없으면 진행 불가) / **권장**(없으면 위험 또는 품질 저하)

### R1. 특징 추출 소스와 정의 — **필수**

6개 특징 각각에 대해 **실행 가능한 원본 코드**와 **정의 문서**를 요청한다. 아래 항목이 모두 드러나야 한다.

| # | 특징 | 확인이 필요한 사항 |
|---|---|---|
| 1 | `HF_Zmag_mean` | "HF"의 정확한 **주파수 구간(Hz)**, 평균 대상(구간 내 주파수점? 반복 측정?), |Z|의 단위(Ω), 평균 방식(산술/기하) |
| 2 | `HF_Zmag_CV` | CV를 **무엇에 대해** 계산하는가(주파수점 간? 반복 간?), 표준편차 자유도(n 또는 n−1), 비율(0.2 = 20%?) |
| 3 | `log_CPE_Yratio_10Hz` | CPE 어드미턴스 **Y**의 정의, **무엇 대비 비율**인가(단계 간? 기준 대비?), 로그의 밑(자연로그/상용), "10Hz" 평가 방식(피팅값에서 계산? 실측 보간?) |
| 4 | `CPE_phase_difference_rad` | 무엇과 무엇의 위상 차인가, 라디안 정의, 부호 규칙 |
| 5 | `logZratio_10k_1k` | 정확히 `ln(\|Z(10kHz)\| / \|Z(1kHz)\|)`인가, 해당 주파수점이 격자에 없으면 보간 방법(로그 주파수 선형 보간?), 로그 밑 |
| 6 | `delta_Rct_Ohm` | **무엇의 변화량인가**(전→후 단계? 기준 대비?), Rct 추출 방식, 부호 규칙 |

공통으로 필요한 정보:
- **등가회로 모델**: 회로 구조(예: Randles + CPE), 각 소자 의미, CPE 식(`Z = 1/(Q·(jω)^α)` 등)과 `Y` 정의
- **피팅 방법**: 사용 라이브러리/알고리즘, **초기값, 경계값, 가중치, 손실 함수, 피팅에 쓴 주파수 구간**
- **피팅 실패 처리**: 수렴 실패·비현실적 값일 때 어떻게 하는가(제외? 기본값? 재측정?)
- **입력 정의**: 주파수/크기/위상 열 이름·단위, 사용하는 측정 단계(§R2), 반복 평균 규칙(§R3)
- **의존 라이브러리와 버전** (scipy, lmfit, impedance.py 등)

제공 형식(우선순위 순): ① 실행 가능한 Python 함수 `extract_features(...) -> dict[6개]` + 사용 예, ② 정의 문서, ③ 데이터 입출력 예시 1건 이상.

**수용 기준**: 제공받은 코드에 §R4 샘플의 원시 스펙트럼을 넣으면 **그 샘플의 6개 특징량이 재현**된다 (허용오차는 아래 §4).

### R2. 측정 프로토콜 — **필수**

| 확인 사항 | 비고 |
|---|---|
| **측정 단계 수와 순서** | 예: 기준(blank) → 시료 반응 → 세척? `delta_Rct`가 전/후 변화량이라면 어떤 두 단계인가 |
| 단계별 **반응·대기 시간**, 단계 사이의 사용자 작업(도포, 세척 등) | GUI 안내 화면·타이머 설계에 필요 |
| 단계별 **반복 측정 횟수** | 요구: 3회 반복. 3회가 단계마다인가, 전체인가 |
| **스윕 설정**: 시작/끝 주파수, 점 수, 로그 간격 여부, 여기 신호 진폭(mVpp), RCAL, RTIA 고정 여부 | 장비 제약: 0.016~200,000Hz, 최대 500점, 진폭 0~800mVpp, 로그 간격 |
| **사용 채널** | 장비 채널 CH0~CH3 중 어느 채널이 NT-proBNP 키트인가. 한 키트에서 Troponin과 같이 측정하는가 |
| 필요한 **환경 조건**(온도·습도 범위) | 장비는 온습도를 함께 기록한다 |
| 측정 전 **SHORT 보정**이 학습/측정 데이터에 적용되었는가 | 장비 출력의 `R_OHM/X_OHM/MAG_OHM/PHASE_DEG`는 SHORT 보정 후 값이다. 학습 데이터가 다른 장비/보정 상태이면 영향이 크다 |
| 학습 데이터를 만든 **측정 장비**가 현재 ADuCM355 장비와 같은가 | 다르면 값 스케일 차이(교차 장비 보정) 문제가 생긴다 |

### R3. 반복 측정 집계 규칙 — **필수**

3회 반복을 **특징 추출 전에** 합치는가, **특징을 각각 구한 뒤** 합치는가?
- 평균인가 중앙값인가, 복소수(R/X)로 합치는가 크기/위상으로 합치는가
- 반복 간 이상치 제외 기준(Troponin 코드는 복소 RMS > 0.08 반복 제외, 고립 스파이크 제거를 쓴다 — 같은 규칙을 쓰는가)
- 학습 시 특징은 **반복 평균 후**에 만든 것인가, 단일 측정에서 만든 것인가 (`HF_Zmag_CV`가 반복 간 CV라면 특히 중요)

### R4. 검증용 실측 샘플 — **필수**

Pi 포팅의 정확성과 특징 추출 구현의 정합성을 확인하기 위해 필요하다.

| 항목 | 요구 |
|---|---|
| 샘플 수 | **최소 20건**(권장 50건 이상), 농도 범위 50~1600 pg/mL **전 구간**을 덮을 것. 범위 밖(<50, >1600) 샘플과 QC 경고가 뜨는 샘플도 각 몇 건 |
| 포함 데이터 | ① **원시 EIS 파일**(모든 측정 단계·반복, 열: `Frequency_Hz, Magnitude_Ohm, Phase_Deg` — Troponin 코드와 같은 형식이면 편함), ② **추출된 6개 특징량**, ③ **정답 농도(pg/mL)**, ④ 모델 출력(`poct_v18.py` 결과 전 필드) |
| 형식 | CSV 또는 xlsx. 샘플 ID, 측정 날짜/배치, 측정 조건 메모 포함 |
| 주의 | `example_V18_features.csv`는 **합성값**이라 검증에 쓸 수 없다 |

### R6. 읽지 못한 모델 수치 — **필수**

정적 분석으로는 읽지 못했고, 모델을 로드해야 알 수 있는 값이다. 다음을 **JSON으로 내보내 주거나**, 우리가 로드해도 좋다는 확인을 요청한다.

| 값 | 용도 |
|---|---|
| `direction_constant` (None인가? 값은?) | 방향 결정 분기 |
| `magnitude_cap` | 보정 크기 상한 |
| `nf_logit_scale`, `f_logit_scale` | 신경망 게이트 스케일 |
| `training_ranges` (6개 특징의 min/max) | 범위 밖 판정(QC) |
| 모든 `StandardScaler`의 `mean_`, `scale_` (direction, magnitude, nf, f, candidate) | 입력 표준화 |
| `LogisticRegression`의 `coef_`, `intercept_`, `Ridge`의 `coef_`, `intercept_` | 방향/크기 모델 |
| `GradientBoostingRegressor`의 트리 배열(`children_left/right`, `feature`, `threshold`, `value`), 초기 상수, `learning_rate`, `n_estimators` | 주 예측 |
| NN 가중치 5세트 | 게이트 |
| `historical_n`, `gate_training_n`, `gate_apply_n`, `gate_reject_n` | 학습 데이터 규모 이해 |

제공 형식(권장): 단일 `V18_weights.json` (또는 `.npz`) + 이를 만든 내보내기 스크립트. 스크립트가 있으면 모델이 갱신되어도 재생성할 수 있다.

### R7. 출력 해석과 화면 표시 기준 — **필수**

| 확인 사항 | 이유 |
|---|---|
| 농도 **단위**(pg/mL 확정인지)와 소수 자리 | 표시 형식 |
| 정량 범위 **밖**일 때(`< 50`, `> 1600`) 화면에 무엇을 표시하는가 | 예: "<50 pg/mL", ">1600 pg/mL" 문구 |
| **임상 컷오프/판정 구간**이 있는가 (예: 정상/주의/위험) | 결과 화면의 판정 문구 |
| `qc_warning`이 True일 때의 처리(결과 표시 + 경고? 결과 숨김 + 재측정?) | UX |
| `p_apply_ensemble_sd` 등 불확실성 필드를 **표시/판정에 쓰는가**, 임계값 | 재측정 권고 조건 |
| 화면에 반드시 넣어야 하는 문구(연구용, 면책, 모델 버전 표기) | 규제/안전 |

### R8. 성능과 검증 상태 — **권장**

- 검증 성능: 구간별 오차(MAE/MAPE/R²), 교차검증 방식, 범위 밖/경계 성능
- 알려진 한계: 키트 로트, 날짜, 온도, 혈액/시료 종류 의존성

### R9. 배치·로트·시간 의존성 — **권장**

Troponin 모델은 같은 배치의 **c0 기준 측정**과 **경과 시간**을 입력에 쓴다. NT-proBNP에도 비슷한 기준 측정(blank/zero)이나 시간 보정이 필요한가? 필요하면 GUI가 **배치 기준 측정 단계**를 추가해야 한다.

## 4. 포팅 검증 합격 기준 (제안)

PC에서 **원본 `poct_v18.py`** 와 **numpy 포팅** 결과를 비교한다.

| 항목 | 기준(제안) |
|---|---|
| 입력 | §R4 샘플의 6개 특징량(전체) + 경계/범위 밖 입력 몇 건 |
| `concentration_pg_mL` | 상대 오차 ≤ **1e-4** (신경망이 float32이므로 1e-6은 요구하지 않음) |
| `p_apply`, `p_up`, `direction`, `qc_warning` | `direction`/`qc_warning`/`direction_source` **완전 일치**, 확률은 절대 오차 ≤ 1e-5 |
| 특징 추출 포팅 | §R4 원시 스펙트럼 → 6개 특징이 **담당자 제공값과 일치**(허용오차는 담당자 정의, 제안 상대 1e-3) |

기준에 이견이 있으면 알려 달라.

## 7. 이 요청이 해결되기 전에 우리가 할 수 있는 일

- Pi 쪽: UART 프로토콜 재작업, 측정 단계 실행기, 결과 저장, Troponin 포팅
- NT-proBNP 쪽: **numpy 추론 틀**(JSON 가중치를 읽는 구조)과 변환 스크립트 뼈대
- 못 하는 것: 특징 추출 구현·검증, 실제 가중치 확인, 표시 문구 확정

## 8. 참고 — 장비가 제공하는 측정 데이터

점(주파수)마다 다음 값을 받을 수 있다 (SHORT 보정 후): `FREQ_HZ`, `MAG_OHM`, `PHASE_DEG`, `R_OHM`, `X_OHM`, 원시 DFT `Z_REAL/Z_IMAG`, `TEMP_C`, `HUM_RH`, `STATUS(OK/SAT)`. 선택적으로 DC 전류(`#D`)와 시간-전류(`#T`)도 가능하다. 상세는 [uart_protocol.md](uart_protocol.md) 참조.

특징 추출이 위 값 이외(예: 시간-전류 곡선, 원시 DFT)를 필요로 하면 알려 달라.
