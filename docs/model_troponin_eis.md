## 2. 측정 프로토콜 (사용법 문서 기준)

| 단계 | 의미 | 반복 | 파일 인자 |
|---|---|---|---|
| **T1** | redox probe 측정 (혈액 반응 **전**) | **3회** | `--t1` |
| **T2** | **혈액 15분 반응 후** 측정 | **3회** | `--t2` |
| **T3** | **세척 후** redox probe 측정 | **3회** | `--t3` |
| **T2 c0** | **같은 날·같은 조건**에서 측정한 **c0 혈액(기준, 농도 0 추정)** 의 T2 | **3회** | `--t2-c0` |

- 코드가 요구하는 "3회 반복"은 각 단계(T1/T2/T3)마다 곡선 3개를 뜻하며, 단계 사이에 **물리적 작업**(혈액 도포, 15분 대기, 세척)이 들어간다. 키트가 **센서 3개 어레이**(사용자 확인)이므로 **센서 3개가 이 3개 곡선**일 가능성이 크다 → 단계당 한 번의 측정(`START 1`, CH0~CH2)으로 충족. 해석은 [models_overview.md](models_overview.md) §0.05 참조(확인 대기).
- `--elapsed-min`: **그 배치 시작 후 T1 측정까지의 경과 시간(분)**. 없으면 Day-1 중앙값(185.74분)을 가정(보정 0)하고 경고.
- `--rtia-ohm`: T1 측정 시 RTIA(Ω). 기본 1000.
- 사용법 문서의 제한 사항: "새로운 날짜에 사용할 때는 **같은 배치의 T2 c0 기준**을 넣는 것이 중요". c0가 없으면 과거 Day-1 앵커값(240.16Ω)을 쓰고 경고한다.

### 입력 파일 형식
- `.xlsx/.xls`: 시트 이름 **`EIS Data`**, 또는 `.csv/.txt`
- 필수 열: **`Frequency_Hz`, `Magnitude_Ohm`, `Phase_Deg`** (NaN 행은 제거)
- T2는 **정확히 101개 주파수점**, 반복 간 **같은 주파수 그리드** (아니면 오류)
- 임피던스 복원: `Z = |Z|·exp(j·phase_rad)`, 주파수 오름차순 정렬

### 2.1 용어 정리: T1 / T2 / T3 / c0 가 각각 무엇인가

| 이름 | 코드·문서에 적힌 설명 | 모델에서의 용도 | 우리의 이해 |
|---|---|---|---|
| **T1** | "redox probe 측정" (혈액 전) | **기준선(baseline)**. `D`의 분모 쪽 (`z1`), 교란 보정의 위상 입력 | **아무것도 없는(혈액 투입 전) 센서의 기준 측정** — 사용자 설명의 ① |
| **T2** | "혈액 15분 반응 후 측정" | **혈액 반응 신호**. `B`의 입력 (`−Im(z2)`, 1~5kHz) | 혈액을 넣고 15분 뒤 측정 — 사용자 설명의 ② |
| **T3** | "세척 후 redox probe 측정" | `D = T3 − T1`의 변화량 (10~50Hz 허수부 상대 변화) | 세척 후 다시 기준 용액으로 측정해 **혈액 투입 후 남은 변화**를 구함 |
| **c0 (T2 c0)** | "같은 날·같은 조건에서 측정한 **c0 혈액** 기준 3회" | `B = (T2 − c0의 T2)/IQR` — **날짜/배치 간 편차를 없애는 기준** | **별도의 기준 혈액(c0)을 T2와 같은 절차로 측정한 값.** T1처럼 "빈 센서"가 **아니다** |

- **c0는 빈 센서가 아니라 "기준 혈액"의 T2 측정값이다.** 코드는 `c0 혈액`, `같은 배치 c0 T2`라고만 쓰며 약어의 뜻을 정의하지 않는다. 이름과 쓰임으로 보아 **c0 = 농도 0(또는 기준 농도) 혈액**으로 **추정**하나, 코드에 정의가 없어 담당자 확인이 필요하다.
- 모델은 빈 센서 기준(T1)과 **별개로** c0 기준을 쓴다. T1은 *같은 센서*의 전후 변화(`D`), c0는 *날짜별* 혈액 신호의 눈금 보정(`B`)이다.
- c0를 못 쓰면 코드는 과거 Day-1 값(`t2_day1_c0_anchor_ohm` = 240.1628 Ω)으로 대체하고 경고한다 — 단, 문서는 "새로운 날짜에 사용할 때는 같은 배치 c0 기준을 넣는 것이 중요"하다고 한다.

## 3. 알고리즘 (코드 순서대로)

### 3.1 반복 평균 — T1, T3 (`aggregate_repeats`)
1. 목표 주파수 = 첫 번째 T1 파일의 주파수.
2. 각 반복을 **log10(주파수) 축에서 선형 보간**(실수부·허수부 각각)해 목표 그리드에 맞춘다. 입력 범위가 목표를 덮지 못하면 오류(`주파수 범위 부족`).
3. 복소 **산술 평균** → `z1`(T1), `z3`(T3).

### 3.2 T2 QC + 집계 (`aggregate_t2_with_qc`, 가장 복잡한 부분)
1. 각 반복 101점, 같은 그리드, **반복 ≥ 2** 조건 확인.
2. `f ≤ 50 kHz` 구간만 사용. 반복 간 **복소 중앙값 곡선** `centre = median(Re) + j·median(Im)`.
3. 반복별 상대 편차 **RMS** = `sqrt(mean(|(z − centre)/denom|²))`, `denom = max(|centre|, 0.02·median|centre|)`.
4. **RMS > 0.08 인 반복은 제외** (`repeat 제외`).
5. 남은 반복에서 **고립 스파이크 점 제거** (`spike_mask`, `f ≤ 50 kHz`):
   - `log|Z|`와 위상(unwrap, °)의 **5점 이동 중앙값 대비 잔차**
   - 임계: 크기 `max(6·robust_σ, 0.06)`, 위상 `max(6·robust_σ, 4°)`; `robust_σ = 1.4826·MAD`
   - 양 끝 2점은 판정 제외. 스파이크 점은 NaN 처리
6. 남은 반복이 **2개 미만이면 오류 → 재측정**.
7. 반복 간 **nan-중앙값**(실/허수 각각) → 목표 그리드로 보간 → `z2`.
- c0 파일도 같은 함수를 거친다.

### 3.3 특징량 D (`corrected_d`) — 주 특징량
1. `relative = 100·(z3 − z1)/|z1|` (%)
2. **`d_raw = median( relative.imag , 10 ≤ f ≤ 50 Hz )`**
3. **위상 기반 교란(nuisance) 보정**
   - `z1`의 위상(°)을 고정 51개 주파수(**20.0 ~ 2828.7 Hz**, log 간격)에서 보간해 로버스트 표준화 → **PCA 2성분**(`pc1`은 부호 `−1` 곱)
   - 교란 벡터 `[pc1, pc2, elapsed_fraction, log10(RTIA)]` 를 로버스트 표준화 후 회귀계수와 내적, 중앙값 차감 → `nuisance`
   - `elapsed_fraction = (elapsed_min − 185.74)/184.35` (경과 시간 없으면 0)
4. **`D = d_raw − 0.65 · nuisance`** (`phase_correction_strength = 0.65`)

### 3.4 특징량 B (`raw_t2_b`) — c0 정규화
1. `t2_raw = median( −z2.imag , 1000 ≤ f ≤ 5000 Hz )` (Ω)
2. 앵커 = 같은 배치 c0의 같은 값(`same_batch_c0`) **또는** 과거 Day-1 값 `240.1628 Ω`(`historical_day1_c0`)
3. **`B = (t2_raw − 앵커) / 29.2007`** (`t2_pooled_c0_iqr_ohm`)

### 3.5 예측 (`predict`)
```
QC:   D_ok = -20.5816 ≤ D ≤ 23.3183     B_ok = -2.5722 ≤ B ≤ 4.1055
D*    = -(D − 7.0341) / 7.8362
B*    =  (B − 0) / 0.78543
score = 0.65·D* + 0.35·B*
pred  = 15.1141 + 10.5339 · score
출력  = clip(pred, 0, 41)   (QC 통과 시에만; 실패 시 숫자를 내지 않음)
```
- **QC 실패 시 농도를 출력하지 않고 "재측정 권장"**을 표시한다 (종료 코드 2).
- 0~41 경계로 잘린 경우 "보정 범위 경계로 제한된 값" 경고.

## 7. GUI/구현 시 고려사항

1. **다단계 작업 흐름**: T1 → (혈액 도포, 15분 대기) → T2 → (세척) → T3, 그리고 같은 배치의 **c0 T2 기준**. 각 단계 사이 안내 화면, 타이머(15분), 단계별 3회 측정이 필요하다. 이는 기존 "3회 반복 → 진단" 설계보다 복잡하다 → [models_overview.md](models_overview.md) §4.
2. **c0 기준 관리**: 같은 날·같은 조건의 c0 측정 결과를 **배치 단위로 저장**하고 재사용할지, 매번 측정할지 결정이 필요하다. 없으면 과거 값 사용 + 경고(정확도 저하 가능).
3. **pandas 제거 권장**: 코드는 파일 입출력에만 pandas를 쓴다. Pi 3A+(RAM 512MB)에서는 numpy만으로 같은 계산을 하도록 포팅하고 **원본 출력과 수치가 일치하는지** 테스트한다 (§8의 두 예시가 기준 값).
4. **파일 대신 메모리 입력**: `read_eis`를 우회해 펌웨어에서 받은 점 목록을 `(freq, Z)`로 직접 넘기는 함수가 필요하다.
5. **QC 실패 UX**: 숫자를 내지 않고 사유(D/B 중 어느 쪽, T2 반복 제외 내역) + "재측정 권장"을 표시.
6. **결과 표시**: 단위가 문서에 없으므로 **화면에 단위를 쓰기 전에 확인**이 필요하다. 성능(MAE≈9, 범위 0~41)을 감안해 **연구용/예비 결과** 표기를 유지한다.
7. 코드 품질 메모: `phase_correction_strength`, 교란 보정 등 하이퍼파라미터가 JSON/코드에 흩어져 있다 → 포팅 시 JSON 버전(`261014-v1`)을 결과에 함께 기록.

## 8. 실행 확인 결과

PC(Python 3.11.6, numpy 2.4.5, pandas 3.0.5)에서 `python -I eis_concentration_predictor.py`를 실행했다.

| 입력 | 결과 |
|---|---|
| `--D 2.9058 --B 1.4012` | `예측 농도: 25.3`, QC PASS, `score=0.9668`, 종료 코드 0 |
| `--D 40 --B 0` | `예측 농도: 출력하지 않음`, QC FAIL (D 범위 초과), 종료 코드 2 |

- 손계산으로도 확인: `D*=0.5268`, `B*=1.7840` → `score=0.9668` → `pred=25.30` ✔
- ⚠️ 사용법 문서는 "`예측 농도: 25.6`처럼 표시"라고 적었으나, 이 입력의 실제 결과는 **25.3**이다 (문서는 형식 예시로 보인다). 포팅 시 기준값은 **25.3**을 사용한다.
- 원시 파일 모드(T1/T2/T3)는 **실측 파일이 없어 실행하지 못했다.** 샘플 데이터 확보 후 포팅 코드와 대조 테스트가 필요하다.

1. **농도 단위**(ng/mL? pg/mL?)와 임상적 의미(컷오프) — **사용자가 별도 확인 예정**
2. ~~스윕 설정~~ → **10Hz~200kHz, 101점 확정**. 남은 것: 신호 진폭, RTIA 고정 여부
3. ~~채널~~ → **센서 3개 어레이 = CH0~CH2 (사용자 확인)**. 남은 것: 3개 센서가 같은 항목의 반복(replicate)인가, 단계마다 시간 반복도 하는가 ([models_overview.md](models_overview.md) §0.05)
4. 샘플 EIS 파일 (포팅 검증용)

## 10. c0 기준 — 담당자 확인 항목

> 목적: Troponin의 **`B` 특징(T2 신호의 날짜/배치 보정)** 이 쓰는 c0 기준의 정의와 운영 방식을 확정한다. 결과에 따라 GUI의 측정 단계 구성과 저장 항목이 달라진다.
> 현재 상태: 코드는 `c0 혈액`, `같은 배치 c0 T2`라고만 쓰고 **정의하지 않는다.** 아래는 코드·문서에서 읽은 것과 우리의 추정이다.

> **피드백 반영 (2026-10-26): "c0 는 첫 번째(센서 0, 1, 2) 측정의 결과 값이다."**
> → 앱은 **1단계(시료준비)에서 측정한 센서 0·1·2 곡선을 c0 로 사용**한다 (`config.ini [measure] c0_source = first`, 기본값). 별도 c0 측정 단계는 필요 없다(아래 C2~C4, S1~S3 대부분 해소). 모델은 이 곡선을 기존 `same_batch_c0` 경로로 받아 T2 와 같은 QC(복소 RMS>0.08 반복 제외, 스파이크 제거)를 거치고, 결과 JSON 에 `anchor_source = same_batch_c0`, `T2_c0_kept`, `T2_c0_anchor_ohm` 이 기록된다. `c0_source = none` 으로 바꾸면 이전처럼 과거 Day-1 값(240.16 Ω) + 경고.
> **아직 확인이 필요한 것**: ① "첫 번째 측정"이 **1단계(시료준비, 모델 T1)와 같은 측정**이 맞는지(우리는 그렇게 해석), ② 그 곡선에 T2 용 계산(−Im(z) 1~5 kHz 중앙값, 29.2007 로 정규화)을 **그대로** 적용하는 것이 의도인지 — 시료 없는 redox 곡선의 값은 과거 앵커(240 Ω)와 크기가 많이 다를 수 있어, **실측으로 B 가 정상 범위에 들어오는지 확인**해야 한다(합성 데이터에서는 B≈7 로 범위를 벗어났다), ③ 7번 이하 C5~C10 은 대부분 불필요해졌지만 담당자 확인 후 정리.

### 10.1 코드에서 확인된 사실
| 사실 | 근거 |

| 사용법 문서: "새로운 날짜에 사용할 때는 **같은 배치 T2 c0 기준**을 넣는 것이 중요" | `EIS_정량코드_사용법.md` |
| 권장 입력: "T2 c0: **같은 날·같은 조건**에서 측정한 c0 혈액 기준 3회" | `EIS_정량코드_사용법.md` |

| # | 질문 | 왜 필요한가 | 답에 따른 GUI 영향 |

### 10.3 답변별 구현 시나리오

| 시나리오 | 설명 | GUI/저장 |
|---|---|---|
| **S1. 사용자가 측정마다 c0를 측정** | 환자 측정 전/후에 c0 3센서 T2를 함께 측정 | 단계 실행기에 c0 단계 추가(15분 반응 포함 가능), 각 측정 결과에 c0 곡선 첨부 |
| **S2. 배치 단위로 한 번 측정해 재사용** | 하루/로트 기준으로 c0를 한 번 측정해 저장, 이후 환자 측정에서 재사용 | **c0 저장소**(값, 측정 시각, 배치 ID, 로트, 온도), 유효 기간 만료 시 재측정 안내, "c0 측정 모드" 화면 |
| **S3. 장비 보관값 사용** | 고정 앵커(240.16Ω) 사용 | 설정에 앵커 값, **모든 결과에 "과거 기준값 사용" 경고**, 새로운 날짜 정확도 저하 주의 |
| **S4. 혼합** | c0가 있으면 사용, 없거나 만료면 보관값 + 경고 | 위 S2+S3, 결과 JSON에 `anchor_source`(`same_batch_c0`/`historical_day1_c0`) 기록 |

> 코드가 이미 S4와 같은 동작을 한다(`anchor_source`). **현재 가정: S4 (확정 전)**. 단, c0 측정 단계를 UI에 넣을지는 C2~C4 답에 달렸다.
