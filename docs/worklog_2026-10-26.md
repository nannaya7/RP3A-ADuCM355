## 3. 세로 화면 아래쪽 잘림 — 원인과 해결
- 증상: 세로 패널에서 모든 화면의 맨 아래가 잘렸다. 처음에는 "보이는 영역이 실제보다 작다"고 보고 아래에 20px 여백을 넣었으나 그대로였다.
- **진짜 원인**: `python main.py -v` 로그에서 화면은 480x800 인데 **전체화면 창이 463x814** 로 떠 있었다. 측정 화면 내용의 최소 높이(787px, 오류 배너가 뜨면 약 +60px)가 최상위 창의 최소 크기가 되어 창이 화면보다 커진 것이다. 창 안쪽 여백은 소용이 없었고, 설정 화면의 키보드도 창 높이를 기준으로 자리를 잡아 같이 밀렸다.
- 해결:
  1. `AppWindow` 의 레이아웃에 `SetNoConstraint` — 페이지 내용이 창 크기를 키우지 못한다 (`app/app_window.py`).
  2. 세로 측정 화면의 본문(프로필~장비 상태)을 `QScrollArea` 에 넣었다 — 평소에는 그대로 보이고 배너 때문에 넘칠 때만 밀어서 본다. 제목줄과 배너는 고정 (`ui/dashboard_portrait.py`).
  3. 세로 모드 아래 안전 여백 20px (`config.ini [display] bottom_margin`, 0~200) 과, 그 위에 붙는 가상 키보드, 여백 띠는 현재 페이지 배경색으로 칠한다.
  4. `python main.py -v` 에 `screen ...` / `window ... size=...` 진단 로그 추가.
- 교훈: 화면이 잘리면 먼저 **`-v` 로 창 크기와 화면 크기를 비교**한다 (`window size` 가 화면보다 크면 내용의 최소 크기 문제).

## 4. 설정 화면 (Wi-Fi / 블루투스)
- **이름 필터**: 입력한 글자를 포함한 항목만 표시 (대소문자 무시, 블루투스는 MAC 일부도). 입력란 옆에 `n / 전체` 표시.
- **정렬**: 신호 세기(RSSI) 순. 연결됨/저장됨은 배지로만 표시 (이전에는 맨 위로 올렸다). 신호 정보 없는 블루투스 장치는 맨 아래.
- 세로에서 필터를 입력하는 동안은 결과 목록을 남기고 상세 카드를 접는다. 필터 입력란은 화면이 열릴 때 포커스를 받지 않는다 (키보드가 저절로 뜨지 않게).

## 5. Troponin c0
- 모델 담당자 피드백 "c0 는 첫 번째(센서 0, 1, 2) 측정의 결과 값" → **1단계(시료준비) 곡선을 c0 로 사용** (`config.ini [measure] c0_source = first`, `none` 이면 이전 방식). 별도 c0 단계는 필요 없다.
- **확인 필요**: "첫 번째 측정"이 1단계가 맞는지, T2 용 계산(−Im(z) 1~5 kHz 중앙값 / 29.2007)을 그대로 적용하는 게 의도인지, 실측에서 B 가 정상 범위인지. 합성 데이터에서는 B≈7 로 범위를 벗어났다. 자세한 내용은 [model_troponin_eis.md](model_troponin_eis.md) §10.
- 가상 펌웨어 데모의 2단계 값을 `150-280j` → `150-112j` 로 바꿨다 (c0 가 첫 측정일 때 B 가 정상 범위가 되도록).

## 5-1. 설정 > 센서 탭 (패치 센서 / 내장 센서)
- 토글 2개, 동시에 하나만 ON (하나를 켜면 다른 하나 자동 OFF, 켜진 것을 끄면 둘 다 OFF). 패치 = 블루투스, 내장 = UART. 선택은 `data/sensor.json` 에 저장, 검사 중에는 변경 거절. 자세한 내용은 [settings_network.md](settings_network.md) §5-1.
- **가정**: 패치 센서는 블루투스 직렬(SPP) 포트(`[sensor] patch_port = /dev/rfcomm0`)로 같은 프로토콜을 쓴다. 실제 통신 방식(SPP/BLE)을 알려 주면 맞춘다. Pi 실기 미확인.
- `UartWorker.set_transport()` 로 실행 중 연결을 바꾼다 (`comm/uart_worker.py`).
- **패치 센서 ON = 연결 + 조회 확인**: 패치 연결로 바꾸고 `STATUS` 응답(컨트롤러 READY)을 기다려, 응답이 있을 때만 켜진 것으로 저장한다. 응답이 없으면 이전 센서로 되돌리고 팝업 "먼저 센서를 연결해 주세요." (사용자 제안 — 처음에 만든 "블루투스 연결 여부 확인"보다 정확해서 교체).
- **테스트 안정화**: 이전 테스트의 창이 닫히지 않고 쌓여 간헐적으로 비정상 종료하던 것을 `tests/conftest.py` 에서 테스트마다 창을 닫고 지우도록 했다 (3회 연속 282개 통과). 원인을 100% 확정한 것은 아니다.

## 5-3. 가로 장비 부팅 화면 (뒤집힘·쏠림)
- 증상: 가로(1280x800) 장비의 부팅 화면 두 단계가 모두 180도 뒤집힘, 로고 화면은 한쪽으로 쏠림.
- 대응(스크립트는 하나, 로고 이미지만 장비별): `install_splash.sh --for landscape|portrait` / `--logo FILE` 추가, 180도 로고 `deploy/boot_logo_landscape_180.png`. `nformare.script` 는 **화면 크기가 바뀔 때마다 로고를 다시 배치**하도록 변경(쏠림 가설: 시작 때 한 번만 읽던 화면 크기가 부팅 중 바뀜). 진단 테마 `deploy/splash_debug.sh on|off` (화면 크기·방향을 화면에 표시). 자세한 내용은 [boot_splash.md](boot_splash.md) §9.
- 가로 장비에서 180도 로고가 90도 어긋남 → 각도를 Pi 에서 바로 바꿔 시험하도록 `install_splash.sh --rotate 0|90|180|270` (`pi_setup.sh --splash-rotate`) 추가 (`deploy/rotate_logo.py`, 시계 방향). 시험 49개 통과(bash).
- **확정(사용자 Pi 실기 확인): 가로 장비는 `--rotate 90` 이 맞다.** `--for landscape` 를 `deploy/boot_logo_landscape_90.png`(시계 방향 90도)로 바꾸고 틀린 `boot_logo_landscape_180.png` 는 삭제. 세로는 270도(기존 확정). 문서(pi_setup.md §4-1, boot_splash.md §9)와 시험 갱신.
- **Pi 미확인**: 새 Plymouth 스크립트는 PC 에서 실행할 수 없어 문법을 눈으로만 확인했다 (이전 버전은 `nformare_static.script.bak`). `--for` 옵션 시험 포함 설치 스크립트 시험 42개 통과(bash).

## 5-5. SD 카드 이미지 복제 준비
- 계획: 한 번 설정한 SD 카드를 이미지로 만들어 여러 장 굽는다. 그대로 복제하면 안 되는 정보(환자 프로필·검사 결과, Wi-Fi 비밀번호, 블루투스 페어링, SSH 호스트 키, machine-id, 터미널 기록)를 이미지 만들기 직전에 `deploy/prepare_image.sh`(`--dry-run`, `--yes`, `--keep-wifi`, `--keep-bluetooth`)로 정리. 복제본의 첫 부팅 서비스 `nformare-firstboot`(`deploy/firstboot.sh` + `.service`)가 SSH 키를 새로 만들고, 부팅 파티션의 `nformare-device.txt`(`hostname=…`)로 호스트 이름을 정한다. 절차·주의는 [pi_setup.md](pi_setup.md) §13. 시험 9개(`tests/test_image_prepare.py`, bash).
- **Pi 미확인**: 실제 Pi 에서 정리 → 이미지 → 굽기 → 부팅은 아직 해 보지 않았다. 가로/세로 이미지는 따로 만든다(패널 overlay, 부팅 로고 방향).
