# UART 모니터링 화면

모듈과 **주고받는 UART 줄을 실시간으로** 보는 화면이다. 모듈이 응답하지 않을 때(예: "STATUS: 응답 시간 초과") 무엇을 보냈고 무엇이 왔는지 바로 확인하려고 만들었다. 읽기 전용이라 명령을 보내지는 못한다 (측정 중 임의 명령이 상태를 흐트러뜨리지 않게).

## 1. 여는 방법
측정 화면 아래쪽 **[모니터링] 버튼** (`중지` 바로 옆. 가로는 `모니터링 · 중지 · 주 버튼`, 세로는 `처음부터 · 중지 · 모니터링`).
`← 뒤로`를 누르면 측정 화면으로 돌아온다. 측정은 모니터링을 보는 동안에도 계속된다.

## 2. 화면
```
  12.345 → STATUS                     보낸 명령 (파란색)
  12.401 ← #I,000123,INFO,ready       모듈이 보낸 줄 (검정)
  12.420 ← #D,...                     측정점 레코드 (회색)
  13.002 ← ERR,BUSY                   모듈 오류 응답 (빨강)
  14.000 • UART 연결 끊김              연결 상태/오류 (주황)
```
- 맨 앞 숫자는 **앱을 켠 뒤 경과 초**다 (Pi 에는 RTC 가 없어 실제 시각 대신 상대 시간을 쓴다).
- 위쪽 체크박스로 `보냄 →` / `받음 ←` / `측정점(#D)` 을 켜고 끈다. 스윕 한 번에 측정점이 수백 줄 오므로 `#D` 를 끄면 명령과 응답만 보인다. 연결/오류 줄은 항상 보인다.
- 상태 줄: `연결됨 · 보냄 N · 받음 N` (+ `일시정지`, 보류 줄 수).
- 맨 아래를 보고 있으면 새 줄을 따라가고, 위로 올려 읽는 중이면 끌어내리지 않는다. 손가락으로 위아래·좌우로 민다 (줄은 접지 않는다).

| 버튼 | 동작 |
|---|---|
| 일시정지 / 계속 | 화면 갱신을 멈춰 읽는다. 멈춘 동안 온 줄은 보류했다가 `계속`에서 한꺼번에 보여 준다 (기록은 계속된다) |
| 지우기 | 기록과 보냄/받음 카운터를 지운다 |
| 저장 | 현재 기록 전체를 `results/monitor/uart_YYYYMMDD_HHMMSS.log` 로 저장한다. 문제를 개발자에게 보낼 때 이 파일을 보낸다 |

## 3. 구조
- `comm/uart_worker.py`: `lineSent`(보낸 줄) 신호 추가. 받은 줄은 기존 `lineReceived`.
- `comm/traffic_log.py` `TrafficLog`: 워커의 보냄/받음/연결/오류 신호를 시간순으로 기록 (링 버퍼 5000줄, 한 줄 300자까지). **앱이 켜져 있는 동안 항상 기록**하므로 화면을 나중에 열어도 그 전 내용이 보인다.
- `ui/monitor_page.py` `MonitorPage`: 0.1초마다 모아서 그린다 (많은 줄이 와도 느려지지 않음), 화면에는 최대 4000줄.
- `app/app_window.py`: `AppWindow.traffic`, `AppWindow.monitor`. 모니터링 화면에서는 설정 버튼을 숨기고, 열기 전 화면으로 돌아온다.
- 시험: `tests/test_monitor.py` (기록, 필터, 일시정지, 저장, 스크롤 추적, 가상 펌웨어 실제 송수신, 버튼 위치).

## 4. 읽는 법 (모듈 인식이 안 될 때)
| 보이는 것 | 뜻 |
|---|---|
| `→ STATUS` 만 있고 `←` 가 없다 | 모듈이 응답하지 않는다: 배선(TX/RX 교차), 전원, 펌웨어 동작, 보레이트 115200 확인 |
| `←` 에 깨진 글자 | 보레이트 불일치 또는 미니 UART 클럭 문제 (`docs/pi_uart_setup.md`) |
| `← #I,...INFO,...` 가 계속 온다 | 모듈은 살아 있다. 명령 응답 형식을 확인 (`docs/uart_protocol.md`) |
| `← ERR,...` (빨강) | 펌웨어가 명령을 거부했다. 앱은 자동으로 `STOP` 을 보낸다 |
| `• UART 연결 끊김` 이 반복 | 포트가 열리지 않거나 끊김 (`dialout` 그룹, `/dev/serial0` 확인) |
