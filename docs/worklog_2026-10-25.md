# 작업 기록 — 2026-10-25

오늘은 로그인 이후의 화면을 크게 늘렸다: **설정(Wi-Fi/블루투스) → UART 모니터링 → 시작 콘솔 정리 → 단계 이름 변경 → 가로/세로 측정 화면(시안 반영)**.
시험은 PC 에서 가상 펌웨어/가상 네트워크로 했고 **전체 250개 통과, 11개 건너뜀**(PowerShell 에서 bash 스크립트 시험이 안 돌아서; bash 로 돌리면 1개만 건너뜀). Pi 실기에서 확인한 것은 §6 에 따로 적었다.

## 1. 설정 버튼 + 설정 화면 (Wi-Fi / 블루투스) — [settings_network.md](settings_network.md)
- 로그인·측정 화면 **우측 상단 톱니바퀴 버튼**(가로/세로 모두). 누르면 설정 화면, `← 뒤로`는 열기 전 화면으로. 측정 중에 열어도 측정은 계속된다. 설정 화면·키보드가 열렸을 때는 버튼을 숨긴다.
- 설정 화면: `Wi-Fi` / `블루투스` 탭. Wi-Fi 는 검색·연결(성공하면 자동 저장)·해제·저장 삭제·직접 입력(숨은 네트워크)·켜기/끄기. 블루투스는 검색(8초)·등록(페어링+신뢰+연결)·연결·해제·삭제·켜기/끄기. PIN/숫자 확인이 필요한 장치는 지원하지 않는다.
- 구조: `net/`(`wifi.py` nmcli, `bluetooth.py` bluetoothctl, `runner.py`, `tasks.py` 백그라운드 실행, 가상 백엔드), `ui/gear_button.py`, `ui/settings_page.py`.
- `tools/net_check.py`: **Pi 에서 진짜 nmcli/bluetoothctl 을 실행**해 원본 출력과 앱의 해석을 나란히 보여 준다 (`--save` 로 보내기, `--connect`/`--bt-register` 등 실제 동작 시험).
- 블루투스 `org.bluez.Error.Busy` (Pi 실기 오류): 부팅 직후 컨트롤러 준비 전에 켜기를 요청해서 생겼다. 1초 간격 12번 재시도, 켜지는 중(`off-enabling`) 대기, 이미 켜졌으면 성공 처리, 끝까지 안 되면 원인(rfkill/서비스/장치 없음)과 해결 명령을 화면에 표시.
- `deploy/pi_setup.sh`: `network-manager bluez rfkill` 설치, 사용자를 `bluetooth` 그룹에 추가.

## 2. UART 모니터링 화면 — [uart_monitor.md](uart_monitor.md)
- 측정 화면 `중지` 옆 **[모니터링]** 버튼 → 모듈과 주고받는 줄을 실시간 표시(`→` 보냄 파랑, `←` 받음 검정, `#D` 회색, `ERR` 빨강, 연결/오류 주황). 필터(보냄/받음/측정점), 일시정지, 지우기, **저장**(`results/monitor/uart_*.log`). 읽기 전용.
- `comm/traffic_log.py`(앱이 켜져 있는 동안 항상 기록, 5000줄 링 버퍼), `ui/monitor_page.py`, `comm/uart_worker.py` 에 `lineSent` 신호.
- 계기: 가로 측정 화면의 "모듈이 응답하지 않습니다 (STATUS: 응답 시간 초과)". 모니터링에서 `→ STATUS` 뒤에 `←` 가 오는지 먼저 본다.

## 3. 시작할 때 콘솔 출력 정리
- `wrong permissions on runtime directory /run/user/1000` → 앱이 시작할 때 내 소유 폴더를 0700 으로 고친다 (`app/logsetup.py`).
- `Wayland does not support QWindow::requestActivate()` → 무해한 경고라 숨김 (다른 Qt 경고/오류는 그대로).
- `INFO …` 로그는 기본 숨김(기본 warning). 보려면 `python3 main.py -v` / `-vv` 또는 `config.ini [app] log_level = info`.

## 4. 단계 이름 변경
- 화면 이름: **시료준비 → 혈액투입 → 세척후 검증** (`measure/stages.py` `STAGE_LABELS`, 모델이 달라도 공통). 내부 식별자 T0/T1/T2(모델 코드 T1/T2/T3)는 결과 파일에 그대로. NT-proBNP 는 담당자와 협의 후 확정.
- 주 버튼 글씨는 모든 단계에서 `측정 시작`.
- 단계별 시간(추정): 측정 약 1~3분/단계(센서 3개 × 20~60초, **실기 확인 필요**), 혈액투입 시작 전 반응 대기 **15분**(`reaction_wait_s = 900`). 응답 130초 무수신 시 중지·오류.

## 5. 측정 화면 (시안 반영) — [measure_dashboard.md](measure_dashboard.md)
**가로(1280x800)** `ui/dashboard_page.py`: 환자 프로필(필수: 성명·성별·나이·몸무게 / 옵션: 혈압·혈당·만성질환) · 검사 결과 · 검사 진행(3단계 카드) · 장비 상태 · 검사 이력. 검사 결과/장비 상태/검사 이력의 왼쪽 끝을 맞췄다(윗줄과 같은 5:3 비율).
**세로(480x800)** `ui/dashboard_portrait.py`: 프로필(가족 구성원) 선택 · 검사 결과 · 3단계 줄(단계별 시작 버튼) · 장비 상태(아이콘 3개) · 검사 이력 보기. 프로필 편집(`ui/profile_edit_page.py`), 이력 화면(`ui/history_page.py`).
공통: `ui/dashboard_logic.py`(표시 로직 하나), `ui/dashboard_widgets.py`(삽화·카드·칩·표), `measure/patient.py`, `measure/profiles.py`(`data/profiles.json`), `measure/history.py`(`summary.json` 읽기).

- **프로필 필수**: 가로는 4개 필수 칸을 채워야, 세로는 프로필을 골라야 1단계 시작 (`config.ini [measure] require_patient`, 기본 true). 결과 파일(`result.json`/`summary.json`)에 환자 정보가 함께 저장된다 → **개인정보**, `results/`·`data/` 반출 주의. 새 측정을 시작하면 환자 정보/선택이 지워진다.
- **단위·참고 범위는 비워 둠** (시안의 `ng/mL`, `0.000–0.040` 은 모델 단위 확정 전이라 쓰면 결과가 전부 "주의"로 나온다). 지금은 숫자만 표시, 정상/주의 판정 없음. 확정되면 `config.ini [result]` (`unit`, `ref_low`, `ref_high`).
- 시안과 다른 점: "키트 1개 사용" 문구 제거, 검사 방법 "면역형광법(FIA)" → "EIS"(장비 방식), 뒤로 가기 `←` 추가, 모니터링/처음부터/중지 버튼 추가, 만성질환 목록과 단계 설명 문구는 임시 (`measure/patient.py`, `ui/dashboard_logic.py`).
- 삭제: `ui/measure_page.py` (이전 임시 세로 화면).

## 6. 버그 / 정리
- **프로그램이 가끔 소리 없이 종료**(테스트 중 `0xC0000409`): `QTimer.singleShot(람다)` 가 화면이 사라진 뒤에 실행되면 PyQt 가 프로그램을 강제 종료한다 → 화면에 묶인 타이머로 교체 (`ui/dashboard_page.py`). 앱에서도 같은 위험이 있던 부분.
- 테스트 정리: `tests/test_net.py`, `test_settings_ui.py`, `test_monitor.py`, `test_logsetup.py`, `test_dashboard.py`, `test_dashboard_portrait.py` 추가, 기존 시험 갱신.
