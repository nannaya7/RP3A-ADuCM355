# 통신 구조와 AT 명령 규칙

내장 보드의 통신 구조와, 앱이 UPS 로 보내는 AT 명령(배터리 확인)의 규칙을 정리한다.

## 1. 연결 구조

```
                  블루투스(BLE NUS)
 ┌────────────┐ ◄───────────────────► ┌──────────────────────┐
 │            │                       │ 패치 센서 (ADuCM355)  │
 │            │                       └──────────────────────┘
 │ 라즈베리파이 │
 │            │      UART             ┌──────────────┐      UART      ┌──────────────────────┐
 │            │ ◄───────────────────► │     UPS      │ ◄────────────► │ 내장 센서 (ADuCM355)  │
 └────────────┘   (/dev/serial0)      │  (STM32)     │                └──────────────────────┘
                                      └──────────────┘
```

- **패치 센서**: 블루투스(NUS)로 파이와 직접 통신한다.
- **내장 센서**: 파이와 직접 연결되지 않고 **UPS 를 거친다**.
- **UPS 는 UART 데이터 허브다.** 파이가 보낸 UART 메시지를 UPS 가 **종류별로 분류해서** 직접 처리하거나 해당 모듈로 보내고, 모듈에서 올라오는 응답·데이터도 UPS 가 모아서 파이로 보낸다.
- **UPS 의 역할**
  - `AT+…` 명령은 UPS 가 **직접 처리**하고 응답한다.
  - 측정 명령(`SWEEP`, `CHAN`, `VERB`, `RTIA`, `START` …)은 **내장 센서로 전달**한다.
  - 내장 센서의 측정 데이터를 파이로 **전달**한다.
- **패치 센서를 쓰는 중에도 UPS 는 유선 UART 의 AT 명령에 응답한다.**
- **허브 구조라서** 파이 입장에서는 한 줄로 AT 응답, 측정 데이터(, 향후 NFC 응답)가 섞여 들어온다. 앞의 "측정 중 AT 금지", "한 번에 하나, 응답 후 다음 명령" 규칙은 이 한 줄에서 응답이 뒤섞이지 않게 하려는 앱 쪽 약속이다.
- **라즈베리파이는 UART 를 1개만 쓴다** (`/dev/serial0`). AT 명령, 측정 명령, 측정 데이터가 모두 이 한 줄로 오간다. 같은 포트를 동시에 두 번 열 수 없으므로 아래 규칙이 필요하다.

## 2. AT 명령 규칙

| 규칙 | 내용 |
|---|---|
| 전송 경로 | AT 명령은 **유선 UART 로만** 보낸다. 블루투스(NUS)로는 보내지 않는다. |
| 측정 중 | 센서 종류(내장/패치)와 상관없이 **측정 중에는 AT 명령을 보내지 않는다.** (모듈 확인·측정 설정·측정·중지 처리·계산 중, 펌웨어가 측정을 진행 중일 때) |
| 순서 | 한 번에 하나만 보내고, **응답을 받은 뒤에 다음 명령**을 보낸다. 응답이 1초 안에 없으면 실패로 보고 다음으로 넘어간다. |
| 줄 끝 | 명령 뒤에 CR+LF(`\r\n`)를 붙인다. 예: `AT+BATT\r\n` |
| 중지 | `STOP` 만은 안전을 위해 큐를 거치지 않고 즉시 보낸다. |

### 2.1 AT+BATT (배터리)

```
[TX] AT+BATT\r\n
[RX] AT+BATT,4.15V,95%\r\n
```

- 앱은 응답에서 전압(V)과 잔량(%)을 읽어 화면 우측 상단 배터리 아이콘에 표시한다.
- 아이콘은 4단계(75 % 이상 4칸, 50 % 이상 3칸, 25 % 이상 2칸, 그 아래 1칸)이고, 잔량(%)이 아이콘 안에 표시된다.
- 값을 알 수 없으면 회색 테두리에 `--` 가 표시된다.

## 3. 배터리 확인 동작 (app/comm/battery.py)

| 상황 | 동작 |
|---|---|
| 앱 시작 | 모듈 확인(ENV) **전에** `AT+BATT` 를 먼저 보내고, 응답이 오거나 1.5 초가 지나면 ENV 로 넘어간다. |
| 평상시 | **1분마다** 확인한다. |
| 측정 중 | 보내지 않는다. 측정이 끝나 막힌 것이 풀리면 1분 주기를 기다리지 않고 **바로 한 번** 확인한다. (방금 읽었으면 생략) |
| 내장 센서 | FirmwareClient 의 **명령 큐**로 보낸다 (다른 명령과 같은 순서 규칙). |
| 패치 센서 | 통신 통로가 BLE 이므로, **유선 포트(`/dev/serial0`)를 따로 잠깐 열어** 보내고 응답을 읽은 뒤 닫는다 (배경 스레드, 최대 1.5 초). 읽는 중에 [검사 시작] 을 누르면 읽기가 끝난 뒤에 측정을 시작한다. |
| 값을 모를 때 | 3 초마다 다시 확인한다. 직전 확인이 실패한 경우도 3 초 뒤에 다시 한다. 성공하면 1분 주기로 돌아간다. |
| 응답 없음 | 직전 값을 유지하다가 **연속 3 번** 읽지 못하면 `--` (알 수 없음)로 바꾼다. |
| 센서 전환·연결 끊김 | 값을 지우지 않는다 (게이지가 갑자기 비지 않게). 곧 다시 확인한다. |

## 4. 참고

- 실행할 때는 항상 **내장 센서**가 켜진다. 패치 센서는 실행 후 설정 > 센서 에서 고른다.
- 패치 센서 모드에서도 UPS 가 켜져 있어야 배터리를 읽을 수 있다.
- PC(Windows)에서는 가상 펌웨어로 동작하며, `AT+BATT` 는 항상 `AT+BATT,4.15V,95%` 로 응답한다.

## 5. 향후 확장 구조 (NFC 모듈 추가 예정)

현재 구조에 **NFC 모듈**이 UPS 의 UART 로 추가될 예정이다 (아직 앱에는 구현되어 있지 않다).

```
                  블루투스(BLE NUS)
 ┌────────────┐ ◄───────────────────► ┌──────────────────────┐
 │            │                       │ 패치 센서 (ADuCM355)  │
 │            │                       └──────────────────────┘
 │ 라즈베리파이 │
 │            │      UART             ┌──────────────┐      UART      ┌──────────────────────┐
 │            │ ◄───────────────────► │     UPS      │ ◄────────────► │ 내장 센서 (ADuCM355)  │
 └────────────┘   (/dev/serial0)      │  (STM32)     │                └──────────────────────┘
                                      │              │      UART      ┌──────────────────────┐
                                      │              │ ◄────────────► │      NFC 모듈         │
                                      └──────────────┘                └──────────────────────┘
```

UPS 가 처리하는 명령은 아래와 같다.

| 명령 | UPS 의 처리 |
|---|---|
| `AT+CMD` | UPS 가 **직접 처리** (예: `AT+BATT`) |
| 측정 명령 | **내장 센서로 전달** |
| `NF+CMD` | **NFC 모듈로 전달** (신규) |
| 내장 센서의 데이터 | 라즈베리파이로 전달 |

NFC(`NF+…`) 명령에도 **AT 명령과 같은 원칙을 지킨다** (확정):
1. **측정 중에는 보내지 않는다.** 센서 종류(내장/패치)와 상관없이 같다.
2. **한 번에 하나만 보내고, 응답을 받은 뒤에 다음 명령**을 보낸다.
3. **유선 UART 로만 보낸다.** 패치 센서(BLE) 모드에서도 지금 배터리 확인처럼 **유선 포트(`/dev/serial0`)를 따로 열어** 보낸다.

구현할 때 주의할 점:
- **UART 가 1개뿐이라** 내장 센서 모드에서는 앱의 통신 담당(UartWorker)이 포트를 계속 열고 있다. 이때 `NF+…` 도 포트를 새로 열지 않고 **같은 명령 큐(FirmwareClient)로** 보내야 한다. 패치 모드에서는 포트가 비어 있으므로 잠깐 열어 보낸다 (배터리 확인과 같은 방식).
- 패치 모드에서는 배터리 확인(AT+BATT)과 NFC(NF+…) 가 **같은 유선 포트를 번갈아 열게** 된다. 두 가지가 겹쳐 열리거나 동시에 나가지 않도록, 유선 명령은 **하나의 경로(순서를 지키는 한 줄)** 로 모아서 처리해야 한다 (원칙 2).
- 원칙 1 때문에 NFC 사용 중에 [검사 시작] 을 누르면 NFC 응답이 끝난 뒤에 측정을 시작한다 (지금 배터리 확인과 같은 방식).

아직 정해지지 않은 것: `NF+…` 명령의 응답 형식과 응답 시간 제한, NFC 를 쓰는 화면·시점.
